Ce TD travaille deux thèmes : les tests unitaires (CM 1) et la spécification de fonction (CM 2). Les exercices sont présentés en deux temps : l'énoncé, puis le corrigé (à déplier) — cherchez d'abord seul, puis comparez.

Rappels — principe des tests unitaires

  • Un jeu de test spécifie, pour une fonction et des paramètres donnés, la valeur de retour ou l'effet (cas d'une liste modifiée en place) attendus.
  • Les jeux de test doivent couvrir le maximum de cas : cas particuliers et cas généraux.
  • L'objectif est de mettre en défaut le code testé, pas seulement de vérifier qu'il marche sur un exemple facile.
  • Boîte noire (avant d'écrire la fonction) ou boîte blanche (le code de la fonction testée est fourni).
Assertion — assert <expression booleenne>, "message d'erreur". Le message est affiché si l'expression est évaluée à False, sinon l'exécution est silencieuse.
Fonction de test — rassemble les jeux de test (assertions) associés à une fonction donnée. Nommage : test_<nom fonction a tester>.
Boîte noire — dans les exercices 1, 3, 4 et 5 (boîte noire), on ne demande pas d'écrire la fonction testée elle-même — uniquement les jeux de test et la fonction de test.

Rappels — spécification de fonction

  • Le type des paramètres et de la (des) valeur(s) de retour.
  • La pré-condition : expression booléenne devant être vérifiée par les paramètres pour que le problème puisse être résolu.
  • La post-condition : expression booléenne devant être vérifiée par la (les) valeur(s) de retour.

Modèle pour l'instrumentation :

def <nom de la fonction>(<param1>, <param2>):
    assert ..., 'Pre-condition'
    ... # CODE DE LA FONCTION
    assert ..., 'Post-condition'
    return ...
Règles — pour garantir que la post-condition est cohérente avec le problème posé, les paramètres de la fonction ne doivent pas être modifiés. Pour les fonctions auxiliaires (qui servent aux tests de propriétés), aucune pré-/post-condition n'est demandée.

Exercices : tests unitaires

Exercice 1 — produit des éléments

On souhaite tester en boîte noire la fonction produit_elements qui accepte en paramètre une liste d'entiers et retourne le produit de ses éléments.

1) Écrire 6 jeux de tests distincts correspondant aux cas suivants : liste vide ; singleton ; listes de longueurs toutes différentes et supérieures à 3 contenant : uniquement des nombres strictement positifs ; uniquement des nombres strictement négatifs ; des nombres non nuls (négatifs et positifs) ; exactement un zéro.

2) Écrire la fonction de test correspondante.

Voir le corrigé

Méthode : 6 jeux de test de longueurs toutes différentes (0, 1, 4, 5, 6, 7), pour bien séparer les cas. Les valeurs attendues sont calculées élément par élément.

def test_produit_elements():
    assert produit_elements([]) == 1, "liste vide : produit neutre"
    assert produit_elements([5]) == 5, "singleton"
    assert produit_elements([1,2,3,4]) == 24, "longueur 4, tous positifs"
    assert produit_elements([-1,-2,-3,-4,-5]) == -120, "longueur 5, tous negatifs"
    assert produit_elements([-2,3,-1,4,-5,6]) == -720, "longueur 6, non nuls melanges"
    assert produit_elements([1,-2,3,0,-4,5,-6]) == 0, "longueur 7, exactement un zero"
    print("tous les tests sont passes")
Pièges — le cas « liste vide » attend 1 (élément neutre du produit) et non 0, comme la somme d'une liste vide vaut 0 (neutre de l'addition). Le cas « exactement un zéro » est un piège classique : un seul 0 annule tout le produit, quels que soient les autres éléments.

Implémentation de référence pour exécuter ces tests (non demandée en boîte noire) :

def produit_elements(liste):
    p = 1
    for v in liste:
        p = p * v
    return p

Exercice 2 — nombre de chiffres

On souhaite tester en boîte blanche la fonction nombre_chiffres qui accepte en paramètre un entier quelconque et retourne son nombre de chiffres. Son code est le suivant :

def nombre_chiffres(n):
    if n < 0:
        n = -n
    k = 1
    while n >= 10:
        n //= 10
        k += 1
    return k

1) Écrire 9 (c'est-à-dire 1 + 2×4) jeux de tests distincts correspondant aux cas suivants : zéro ; condition du if fausse ou vraie et, dans chacun des cas : pas d'itération ; exactement 1 itération ; exactement 4 itérations ; plus de 10 itérations.

2) a) Donner les 2 entiers consécutifs tels qu'il y ait 2 itérations pour le premier et 3 itérations pour son successeur. b) Écrire les 2 assertions de test correspondantes.

Voir le corrigé

1) Les 9 jeux de tests (le code fourni a été exécuté pour vérifier chaque valeur attendue) :

def test_nombre_chiffres():
    assert nombre_chiffres(0) == 1, "zero"
    # if faux (n>=0) :
    assert nombre_chiffres(7) == 1, "0 iteration"
    assert nombre_chiffres(42) == 2, "1 iteration"
    assert nombre_chiffres(12345) == 5, "4 iterations"
    assert nombre_chiffres(123456789012) == 12, "plus de 10 iterations"
    # if vrai (n<0) :
    assert nombre_chiffres(-7) == 1, "0 iteration"
    assert nombre_chiffres(-42) == 2, "1 iteration"
    assert nombre_chiffres(-12345) == 5, "4 iterations"
    assert nombre_chiffres(-123456789012) == 12, "plus de 10 iterations"
    print("tous les tests sont passes")

Le nombre d'itérations vaut (nombre de chiffres − 1) : 0, 1, 4 et 11 itérations pour 7, 42, 12345 et 123456789012.

2) a) Il faut que n passe de 3 chiffres à 4 chiffres : n = 999 et n+1 = 1000.

# 999 -> 999 -> 99 -> 9 : 2 iterations, k = 1+2 = 3 chiffres
# 1000 -> 1000 -> 100 -> 10 -> 1 : 3 iterations, k = 1+3 = 4 chiffres

b) Les 2 assertions correspondantes :

assert nombre_chiffres(999) == 3, "999 : 2 iterations, 3 chiffres"
assert nombre_chiffres(1000) == 4, "1000 : 3 iterations, 4 chiffres"

Exercice 3 — insertion ordonnée

On souhaite tester la fonction insertion_ordonnee qui accepte en paramètres liste (une liste d'entiers triée par ordre croissant, au sens large) et valeur (un entier). La fonction insère valeur dans une copie de liste de telle façon que la nouvelle liste reste triée, et retourne la liste ainsi créée. Exemple : si liste vaut [7,11] et valeur vaut 9, l'insertion a lieu à l'indice 1, et la liste retournée est [7,9,11].

1) a) Écrire 5 jeux de tests distincts correspondant aux cas suivants : liste vide ; liste de longueur 4 avec insertion en début, en fin, à une autre position, ou avec une valeur égale à un élément déjà présent (cas « au sens large »). b) Écrire les lignes de code (avec assertions) nécessaires à la vérification du dernier jeu de test. On vérifiera en particulier que la fonction ne modifie pas la liste passée en paramètre.

2) On souhaite au contraire que la fonction ait pour effet de modifier la liste passée en paramètre, sans rien retourner. Écrire les lignes de code (avec assertions) nécessaires à la vérification du dernier jeu de test selon ce nouveau principe.

Voir le corrigé

1) a) 5 jeux de tests. Le 5e (valeur égale à un élément présent) couvre la clause « au sens large » : la liste reste valide qu'on insère avant ou après les éléments égaux, seul le multi-ensemble des valeurs compte.

CasAppelRetour attendu
liste videinsertion_ordonnee([], 5)[5]
insertion en débutinsertion_ordonnee([3,5,7,9], 1)[1,3,5,7,9]
insertion en fininsertion_ordonnee([2,4,6,8], 10)[2,4,6,8,10]
insertion au milieuinsertion_ordonnee([3,7,9,11], 8)[3,7,8,9,11]
valeur déjà présenteinsertion_ordonnee([2,4,4,6], 4)[2,4,4,4,6]

b) Vérification du 5e jeu, avec contrôle de non-modification de la liste d'origine :

liste_originale = [2,4,4,6]
resultat = insertion_ordonnee(liste_originale, 4)
assert resultat == [2,4,4,4,6], "la valeur doit etre inseree en gardant la liste triee"
assert liste_originale == [2,4,4,6], "la liste passee en parametre ne doit pas etre modifiee"

2) Version « effet de bord » (modifie liste en place, ne retourne rien) :

liste = [2,4,4,6]
resultat = insertion_ordonnee(liste, 4)
assert resultat is None, "cette version ne doit rien retourner"
assert liste == [2,4,4,4,6], "la liste doit etre modifiee en place"
Deux conventions — pour une fonction qui « transforme » une liste : retourner une copie (la liste d'origine est intacte, plus sûr mais recopie la mémoire) ou modifier en place (plus économe en mémoire, mais effet de bord à documenter clairement).

Implémentations de référence (non demandées) pour exécuter ces tests — copie, puis en place :

def insertion_ordonnee(liste, valeur):
    resultat = []
    inseree = False
    for v in liste:
        if not inseree and valeur <= v:
            resultat.append(valeur)
            inseree = True
        resultat.append(v)
    if not inseree:
        resultat.append(valeur)
    return resultat
def insertion_ordonnee(liste, valeur):
    i = 0
    while i < len(liste) and liste[i] < valeur:
        i += 1
    liste.append(None)
    for j in range(len(liste) - 1, i, -1):
        liste[j] = liste[j - 1]
    liste[i] = valeur

Exercice 4 — valeurs inférieures (intermédiaire)

Écrire les jeux de tests et la fonction de test associés à nb_valeurs_inferieures(liste, valeur), qui détermine et retourne le nombre d'éléments de liste dont la valeur est inférieure ou égale à valeur. Exemple : si liste vaut [-3,2,8,1,7,11,3,4] et valeur vaut 3, la fonction retourne 4 (valeurs -3, 2, 1, 3).

Voir le corrigé
def test_nb_valeurs_inferieures():
    assert nb_valeurs_inferieures([-3,2,8,1,7,11,3,4], 3) == 4, "exemple de l'enonce"
    assert nb_valeurs_inferieures([], 5) == 0, "liste vide"
    assert nb_valeurs_inferieures([10,20,30], 5) == 0, "aucune valeur ne convient"
    assert nb_valeurs_inferieures([1,2,3], 100) == 3, "toutes les valeurs conviennent"
    assert nb_valeurs_inferieures([5,5,5,2], 5) == 4, "egalite (<=), plusieurs occurrences"
    print("tous les tests sont passes")

Le dernier cas teste spécifiquement le « ou égal » de l'énoncé. Attention : une implémentation buguée utilisant < au lieu de <= est déjà démasquée par l'exemple de l'énoncé (elle renvoie 3 au lieu de 4, car la valeur 3 n'est pas comptée) ; le dernier cas la démasque avec plusieurs occurrences égales (elle renvoie 1 au lieu de 4).

Implémentation de référence :

def nb_valeurs_inferieures(liste, valeur):
    nb = 0
    for v in liste:
        if v <= valeur:
            nb += 1
    return nb

Exercice 5 — indices (intermédiaire)

Écrire les jeux de tests et la fonction de test associés à indices_valeur(liste, valeur), qui détermine et retourne la liste des indices de liste où l'on peut trouver valeur. Exemple : si liste vaut [11,23,67,23,23,83,23,10] et valeur vaut 23, la fonction retourne [1,3,4,6].

Voir le corrigé
def test_indices_valeur():
    assert indices_valeur([11,23,67,23,23,83,23,10], 23) == [1,3,4,6], "exemple de l'enonce"
    assert indices_valeur([1,2,3], 9) == [], "valeur absente"
    assert indices_valeur([], 5) == [], "liste vide"
    assert indices_valeur([4,5,6], 5) == [1], "une seule occurrence"
    assert indices_valeur([7,7,7], 7) == [0,1,2], "toutes les positions"
    print("tous les tests sont passes")

On teste le cas général (exemple), les cas extrêmes (liste vide, valeur absente), une occurrence unique et le cas où toutes les positions conviennent. Implémentation de référence :

def indices_valeur(liste, valeur):
    indices = []
    for i in range(len(liste)):
        if liste[i] == valeur:
            indices.append(i)
    return indices

Exercices : spécification de fonction

Exercice 6 — lecture d'énoncé

Écrire la spécification des fonctions suivantes :

  • 1) La fonction puissance calcule et retourne la puissance p = ab de deux entiers positifs a et b.
  • 2) La fonction log2_entier accepte en paramètre un entier n strictement positif et retourne l'unique entier k tel que 2k ≤ n < 2k+1.
Voir le corrigé

1) Fonction puissance. Types : a, b, p entiers. Pré-condition : a >= 0 and b >= 0 (deux entiers positifs). Post-condition : p == a**b (avec la convention usuelle 00 = 1).

2) Fonction log2_entier. Types : n, k entiers. Pré-condition : n >= 1 (strictement positif). Post-condition : 2**k <= n < 2**(k+1) : k est le logarithme en base 2 de n arrondi à l'entier inférieur ; bien que l'énoncé parle d'un entier « positif », k peut valoir 0 (n = 1).

def puissance(a, b):
    assert a >= 0 and b >= 0, 'Pre-condition'
    p = 1
    for _ in range(b):
        p = p * a
    assert p == a**b, 'Post-condition'
    return p

def log2_entier(n):
    assert n >= 1, 'Pre-condition'
    k = 0
    while 2**(k+1) <= n:
        k += 1
    assert 2**k <= n < 2**(k+1), 'Post-condition'
    return k

(Les implémentations ci-dessus, non demandées, illustrent le modèle d'instrumentation et ont été exécutées : puissance(2,10) == 1024, log2_entier(17) == 4.)

Exercice 7 — écriture de fonction auxiliaire

On souhaite écrire la pré-condition pour l'exercice 3 (insertion_ordonnee).

1) Écrire la fonction auxiliaire est_croissante qui accepte en paramètre une liste d'entiers liste, vérifie que cette liste est triée par ordre croissant (au sens large) et retourne le booléen correspondant. 2) En déduire l'assertion de pré-condition de insertion_ordonnee. (L'écriture de la post-condition dépasse le cadre de ce TD.)

Voir le corrigé

1)

def est_croissante(liste):
    for i in range(len(liste)-1):
        if liste[i] > liste[i+1]:
            return False
    return True

Liste vide et singleton → True par convention ; liste triée (avec égalités) → True ; liste non triée → False. (Ce code a deux return : c'est permis pour une fonction auxiliaire non instrumentée ; la règle du return unique concerne les fonctions avec pré/post-condition.)

2) Pré-condition déduite pour insertion_ordonnee :

assert est_croissante(liste), "liste doit etre triee par ordre croissant (au sens large)"

Exercice 8 — comprendre une spécification

On donne la spécification : type du paramètre : n est un entier ; type de la valeur de retour : a est un entier ; pré-condition : n >= 0 ; post-condition : a >= 0 and a**2 <= n < (a+1)**2. On répondra dans l'ordre souhaité : écrire une implémentation de cette spécification, puis décrire la nature du problème posé et en déduire un nom pertinent pour la fonction.

Contrainte — ne pas utiliser de type float, qui limiterait le domaine de validité de la fonction.
Voir le corrigé

Implémentation (sans float, par recherche incrémentale) :

def racine_carree_entiere(n):
    assert n >= 0, 'Pre-condition'
    a = 0
    while (a+1)**2 <= n:
        a += 1
    assert a >= 0 and a**2 <= n < (a+1)**2, 'Post-condition'
    return a

Vérifiée contre math.isqrt sur une large plage, y compris juste avant/après des carrés parfaits (15/16, 99/100).

Nature du problème : la post-condition a**2 <= n < (a+1)**2 caractérise exactement la racine carrée entière (partie entière de la racine carrée) de n : le plus grand entier dont le carré ne dépasse pas n. Nom pertinent : racine_carree_entiere (équivalent de math.isqrt en Python).

Exercice 9 — complément sur les ternaires (avancé)

On souhaite écrire la fonction nombre_chiffres qui accepte en paramètre un entier positif ou nul n et retourne son nombre k de chiffres (en base 10).

  • 1) Écrire la pré-condition de cette fonction.
  • 2) a) Écrire la fonction auxiliaire est_nombre_chiffres(n,k) qui retourne le booléen indiquant si k est le nombre de chiffres (en base 10) de l'entier positif ou nul n. Indication : un entier strictement positif a k chiffres si et seulement s'il appartient à l'intervalle [10k-1 ; 10k[. L'exception est l'entier 0, qui possède 1 chiffre. b) En déduire la post-condition de nombre_chiffres.
  • 3) Réécrire cette post-condition sous forme d'une expression ternaire (valeur_vrai if condition else valeur_faux).
  • 4) Écrire la fonction nombre_chiffres. Le paramètre n ne doit pas être modifié par la fonction.
  • 5) (Pour aller plus loin) Généraliser dans le cas des nombres relatifs.
Voir le corrigé

1) Pré-condition :

assert n >= 0, 'Pre-condition'

2) a) Fonction auxiliaire :

def est_nombre_chiffres(n, k):
    if n == 0:
        return k == 1
    return 10**(k-1) <= n < 10**k

b) Post-condition déduite (via la fonction auxiliaire) :

assert est_nombre_chiffres(n, k), 'Post-condition'

3) Même post-condition, réécrite avec un ternaire (sans fonction auxiliaire) :

assert (k == 1 if n == 0 else 10**(k-1) <= n < 10**k), 'Post-condition'

4) Fonction complète. Le paramètre n n'est pas modifié : on travaille sur une copie locale m (règle 1).

def nombre_chiffres(n):
    assert n >= 0, 'Pre-condition'
    m = n
    k = 1
    while m >= 10:
        m //= 10
        k += 1
    assert (k == 1 if n == 0 else 10**(k-1) <= n < 10**k), 'Post-condition'
    return k

Vérifiée sur de nombreux n : k coïncide avec len(str(n)).

5) Pour les relatifs, on applique nombre_chiffres à la valeur absolue :

def nombre_chiffres_relatif(n):
    return nombre_chiffres(abs(n))

Vérifiée sur −42, −1, 0, 1, 42, −12345, 12345.

À retenir —
  • Jeu de test : viser le maximum de cas distincts (vide, singleton, cas général, cas limites, égalité stricte vs large) — l'objectif est de mettre en défaut le code, pas de le rassurer.
  • Boîte noire (fonction non fournie) : on écrit seulement les jeux de test d'après l'énoncé ; boîte blanche (code fourni) : on cible les branches et le nombre d'itérations (0, 1, plusieurs) pour tout couvrir.
  • Copie vs effet de bord : une fonction qui retourne une nouvelle valeur sans toucher à ses paramètres, ou qui modifie en place et ne retourne rien (None) — à distinguer dans les tests.
  • Spécification : type + pré-condition (paramètres) + post-condition (retour) ; la pré-condition peut s'appuyer sur une fonction auxiliaire (est_croissante) et la post-condition s'écrire avec ou sans ternaire.
  • Ne jamais modifier les paramètres d'une fonction dont on vérifie une post-condition : travailler sur une copie locale (m = n).
