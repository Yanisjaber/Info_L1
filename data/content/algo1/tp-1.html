Ce TP porte sur l'environnement de travail et sur les tests unitaires : trouver le jeu de test qui révèle un bug, corriger, compléter une fonction de test en boîte noire ou blanche, distinguer copie et effet de bord. Cherchez d'abord seul, puis dépliez le corrigé.

Organisation et environnement de travail

Chaque TP est composé d'un fichier PDF (énoncé) et d'un ou plusieurs fichiers Python à compléter pendant la séance, téléchargeables sur Moodle (onglet « TP »). Il faut organiser ses fichiers dans des répertoires cohérents (répertoire dédié si travail sur machine de l'université). Une zone de dépôt existe pour son propre confort mais le dépôt n'est pas obligatoire et n'est pas corrigé par l'encadrant·e.

CC3 et CC4 — ils se déroulent sur une machine de l'université, sous un environnement Windows spécifique qui met à disposition IDLE, VS Code et PyCharm — aucun autre outil. Il faut donc se familiariser avec l'un de ces trois environnements pendant les séances de TP, pas seulement utiliser Basthon en ligne.

Rappels — principe des tests unitaires

  • Un jeu de test spécifie, pour une fonction et des paramètres donnés, la valeur de retour ou l'effet attendu (cas d'une liste modifiée en place).
  • Les jeux de test doivent couvrir le maximum de cas possibles : cas particuliers et cas généraux.
  • L'objectif est de mettre en défaut le code testé, pas seulement de vérifier qu'il marche sur un exemple facile.
Assertion — assert <expression booleenne>, "message d'erreur". Sémantique : le message est affiché seulement si l'expression vaut False ; sinon l'exécution est silencieuse. Convention : les jeux de test d'une fonction f sont rassemblés dans une fonction de test test_f.

Exercice 1 — palindrome (facile)

ex01_palindrome.py fournit est_palindrome (True si la chaîne est un palindrome) et sa fonction de test. La fonction est mal conçue et le jeu de test ne le révèle pas.

def est_palindrome(mot):
    debut = 0
    fin = len(mot) - 1
    while debut != fin:
        if not mot[debut] == mot[fin]:
            return False
        debut += 1
        fin -= 1
    return True
  • Ajouter au jeu de test l'assertion assert est_palindrome('abba')==True et exécuter le fichier. Que se passe-t-il ?
  • Corriger la fonction pour qu'elle fonctionne sur ce cas.
  • Valider la correction avec la chaîne vide et un contre-exemple non-palindrome de longueur paire.
Voir le corrigé

1) Ajout du test 'abba'. On constate une erreur à l'exécution (IndexError : index hors limites), jamais un simple False. À chaque tour, debut augmente de 1 et fin diminue de 1 : l'écart debut - fin varie de 2 en 2. Pour une chaîne de longueur paire, cet écart part d'une valeur impaire (-3 pour 'abba') : il ne peut jamais valoir 0, la condition debut != fin reste vraie, les indices se croisent et sortent des bornes. La boucle ne s'arrête correctement que pour les longueurs impaires (écart initial pair).

2) Correction : une condition d'arrêt qui reste valable quand les indices se croisent (< au lieu de !=) :

def est_palindrome(mot):
    debut = 0
    fin = len(mot) - 1
    while debut < fin:
        if not mot[debut] == mot[fin]:
            return False
        debut += 1
        fin -= 1
    return True

3) Validation avec la chaîne vide (trivialement palindrome : la boucle ne s'exécute jamais) et un contre-exemple pair non-palindrome :

assert est_palindrome('abba')==True
assert est_palindrome('')==True
assert est_palindrome('abcdba')==False

Exercice 2 — maximum (facile)

ex02_maximum.py fournit maximum (plus grand élément d'une liste non vide d'entiers) et sa fonction de test, mal conçue : il manque un cas qui révélerait une erreur.

def maximum(liste):

    for e in liste:
        if e>m:
             m = e
    return m
  • Trouver un jeu de valeurs qui révèle une erreur dans la fonction, et l'ajouter au test.
  • Corriger la fonction (une modification minimale, une seule ligne, suffit).
Voir le corrigé

1) Cas oublié : une liste ne contenant que des nombres négatifs. L'accumulateur est initialisé à m = 0, jamais dépassé par un négatif : la fonction renvoie 0 au lieu du vrai maximum.

def maximum(liste):

Exercice 3 — répétitions consécutives (facile)

eliminer_repetitions_consecutives remplace dans la liste passée en paramètre toute séquence de 2 entiers identiques consécutifs (ou plus) par un seul — effet sur la liste, retourne None. Le jeu de test est incomplet.

def eliminer_repetitions_consecutives(liste):
    i = 1
    while i<len(liste):
        if liste[i]==liste[i-1]:
           liste.pop(i)
        i += 1
  • Trouver un cas non couvert par les tests fournis qui révèle une erreur (indice : le nombre d'occurrences identiques consécutives).
  • Corriger la fonction en ne modifiant que la structure de contrôle, sans ajouter de ligne de calcul.
Voir le corrigé

1) Cas oublié : une séquence de trois occurrences identiques ou plus (les cas fournis n'en ont que deux à la fois). Exemple : [1,5,5,5,2] devrait donner [1,5,2].

liste = [1,5,5,5,2]
assert eliminer_repetitions_consecutives(liste)==None and liste==[1,5,2]

Avec le code d'origine, ce cas échoue : après un pop(i), l'indice i est quand même incrémenté, alors que l'élément qui vient de glisser en position i n'a pas été recomparé. Pour [1,5,5,5,2] : un seul doublon est éliminé, on obtient [1,5,5,2].

2) Correction minimale (structure de contrôle uniquement) : ne faire avancer i que lorsqu'il n'y a pas eu de suppression, avec un else :

def eliminer_repetitions_consecutives(liste):
    i = 1
    while i<len(liste):
        if liste[i]==liste[i-1]:
           liste.pop(i)
        else:
           i += 1

def est_strictement_croissante(liste):

Exercice 7 — deux miroirs (intermédiaire)

Objectif : écrire une fonction miroir d'une liste (éléments dans l'ordre inverse), sans [::-1] ni .reverse() — uniquement des boucles avec accès par indice et .append() / .pop() / .insert(). Deux fonctions sont demandées, à distinguer grâce à leurs tests :

  • miroir_A : les tests vérifient que la liste d'origine est intacte après l'appel et que la valeur retournée est la liste inversée.
  • miroir_B : les tests vérifient que l'appel retourne None et que c'est la liste passée en paramètre qui se retrouve inversée.
Voir le corrigé

miroir_A : on construit une liste neuve en parcourant l'originale à l'envers par indice, sans jamais la modifier.

def miroir_A(liste):
    resultat = []
    n = len(liste)
    for i in range(n):
        resultat.append(liste[n-1-i])
    return resultat

miroir_B : on échange les éléments symétriques deux à deux, directement dans la liste (lecture/écriture par indice).

def miroir_B(liste):
    n = len(liste)
    for i in range(n//2):
        liste[i], liste[n-1-i] = liste[n-1-i], liste[i]

n//2 échanges suffisent : pour une longueur impaire, l'élément du milieu reste à sa place (il est son propre miroir), aucun traitement particulier n'est nécessaire.

Exercice 8 — fonctions mystères (avancé)

Aucun énoncé fonctionnel n'est donné : il faut deviner ce que font mystere_1(liste, n) (retourne une nouvelle liste, n'y touche pas) et mystere_2(liste, n) (même résultat, mais par effet de bord, sans retour) uniquement à partir des assertions du fichier fourni :

liste = [9,5,10]
assert mystere_1(liste,0) == [9,5,10]
assert mystere_1(liste,1) == [5,10,9]
assert mystere_1(liste,2) == [10,9,5]
assert mystere_1(liste,3) == [9,5,10]

liste2 = [8,5,6,13,2,8]
assert mystere_1(liste2,8) == [6,13,2,8,8,5]
assert mystere_1(liste2,-666) == [8,5,6,13,2,8]
  • En déduire, à partir de ces assertions, ce que calculent mystere_1 et mystere_2.
  • Implémenter les deux fonctions.
Voir le corrigé

Déduction. Pour liste = [9,5,10] : mystere_1(liste,1)==[5,10,9], (liste,2)==[10,9,5] et (liste,3)==[9,5,10] (retour au point de départ). Les valeurs négatives ou très grandes de n donnent un résultat cohérent avec n modulo la longueur de la liste. C'est une rotation vers la gauche de n positions : les n % taille premiers éléments passent à la fin.

Vérification sur [8,5,6,13,2,8] (taille 6) : n=8 → 8%6=2 → rotation de 2 → [6,13,2,8,8,5] ; n=-666 → -666%6=0 → liste inchangée. (En Python, % avec un diviseur positif donne un résultat positif, y compris pour un n négatif : -1 % 6 == 5.)

mystere_1 — nouvelle liste, sans modifier l'originale :

def mystere_1(liste, n):
    taille = len(liste)
    if taille == 0:
        return []
    d = n % taille
    return liste[d:] + liste[:d]

mystere_2 — même rotation, par effet de bord : on retire les d premiers éléments et on les remet à la fin, sur l'objet liste lui-même :

def mystere_2(liste, n):
    taille = len(liste)
    if taille == 0:
        return
    d = n % taille
    partie = liste[:d]
    del liste[:d]
    liste.extend(partie)
Sans if — chaque fonction ne contient qu'un seul if (liste vide : éviter la division par zéro). Une version sans aucun if existe : remplacer taille par len(liste) or 1 dans le calcul de d (court-circuit : si la liste est vide, len(liste) vaut 0 donc or 1 le remplace par 1 ; le résultat reste une liste vide).
def mystere_1_sans_if(liste, n):
    d = n % (len(liste) or 1)
    return liste[d:] + liste[:d]
À retenir —
  • Boîte noire (ex. 5) : cas choisis depuis la spécification, sans lire le code ; boîte blanche (ex. 6) : cas choisis depuis les chemins d'exécution du code (valeur de retour × nombre d'itérations).
  • Trois bugs corrigés : palindrome (while debut != fin ne gère pas les longueurs paires → <), maximum (accumulateur initialisé à 0 au lieu de liste[0], faux si tous les nombres sont négatifs), répétitions consécutives (indice incrémenté même après une suppression : else pour n'avancer que sans suppression).
  • Ex. 4, 5, 6 : il ne fallait pas réécrire les fonctions testées, seulement compléter les fonctions de test avec les bons cas.
  • Ex. 7 et 8 : distinguer une fonction qui retourne une nouvelle valeur sans toucher au paramètre d'une fonction qui modifie en place et retourne None — la forme des tests le révèle.
