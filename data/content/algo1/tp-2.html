Ce TP travaille la spécification de fonction : écrire pré- et post-condition dans des fonctions dédiées (exercices 1 à 3, 7), implémenter selon une spécification donnée (4 à 6), puis des exercices d'entraînement (8 à 10). Cherchez d'abord seul, puis dépliez le corrigé.

Rappels — spécification de fonction

  • Le type des paramètres et valeurs de retour.
  • La pré-condition : condition devant être vérifiée par les paramètres afin que le problème puisse être résolu.
  • La post-condition : condition devant être vérifiée par la (les) valeur(s) de retour.

Les assertions sont placées en tout début et en toute fin de la fonction testée :

def <nom de la fonction>(<param1>,<param2>):
    assert ..., 'Pre-condition'
    ... # CODE DE LA FONCTION
    assert ..., 'Post-condition'
    return ...

Écriture de spécification (exercices 1 à 3)

Le code de la fonction étudiée est donné ; on écrit la pré- et la post-condition dans des fonctions dédiées :

def verifie_pre_condition(...,...):
    return ... # Pre-condition

def verifie_post_condition(...,...):
    return ... # Post-condition

def <nom de la fonction>(<param1>,<param2>):
    assert verifie_pre_condition(...,...), 'Pre-condition'
    ... # CODE DE LA FONCTION
    assert verifie_post_condition(...,...), 'Post-condition'
    return ...
Examen — lors d'un examen, les fonctions test_verifie_pre_condition et test_verifie_post_condition ne seront pas fournies (une partie des points reste possible pour une condition partiellement correcte : comparaison large au lieu de stricte, encadrement incomplet, indice non vérifié avant accès à une liste). Dans ce TP, il faut décommenter ces fonctions de test (et leurs appels) pour vérifier ses propres conditions.

Implémentation selon une spécification (exercices 4 à 6)

La pré- et la post-condition sont données ; on complète le corps de la fonction. Contraintes : les paramètres ne doivent pas être modifiés, et un seul return est autorisé (sauf fonctions auxiliaires).

Exercice 1 — division euclidienne (facile)

Contraintes : division_euclidienne et les fonctions de test ne doivent pas être modifiées ; les opérateurs // et % sont interdits. Rappel : pour a, b entiers positifs (b non nul), le quotient q et le reste r sont les uniques entiers tels que a = q·b + r, avec r ∈ [0 ; b[.

def verifie_pre_condition(a,b):
    return ...

def verifie_post_condition(a,b,q,r):
    return ...

def division_euclidienne(a,b):
    assert verifie_pre_condition(a,b), 'Pre-condition'
    q, r = 0, a
    while r >= b:
        q, r = q+1, r-b
    assert verifie_post_condition(a,b,q,r), 'Post-condition'
    return q, r
  • 1) Compléter verifie_pre_condition(a,b).
  • 2) Compléter verifie_post_condition(a,b,q,r).
  • 3) Décommenter les fonctions de test pour vérifier.
Voir le corrigé

Pré-condition : a et b positifs, b non nul.

def verifie_pre_condition(a,b):
    return a>=0 and b>=1

Post-condition : le reste doit être dans [0 ; b[, et l'égalité a = q·b + r doit être vérifiée :

def verifie_post_condition(a,b,q,r):
    return 0<=r<b and a==q*b+r

Les 3 fonctions de test (pré, post, division_euclidienne(43,10)==(4,3), etc.) passent sans erreur. Les tests de verifie_post_condition incluent des couples faux : (10,3,2,4) (reste trop grand), (10,3,4,-2) (reste négatif), (10,3,4,1) (égalité fausse).

Exercice 2 — calcul du minimum (facile)

Contraintes : calculer_minimum et les fonctions de test ne doivent pas être modifiées ; l'expression m in liste est interdite.

def est_membre(liste,m):
    ...

def est_minorant(liste,m):
    ...

def verifie_pre_condition(liste):
    return ...

def verifie_post_condition(liste,m):
    return ...

def calculer_minimum(liste):
    assert verifie_pre_condition(liste), 'Pre-condition'
    m = liste[0]
    for e in liste:
        if e<=m:
            m = e
    assert verifie_post_condition(liste,m), 'Post-condition'
    return m
  • 1) a) Écrire est_membre(liste,m) : m est-il un élément de liste ? b) Écrire est_minorant(liste,m) : m est-il ≤ tous les éléments de liste ?
  • 2) Compléter verifie_pre_condition(liste).
  • 3) Compléter verifie_post_condition(liste,m) (s'appuyer sur est_membre et est_minorant).
  • 4) Décommenter les tests.
Voir le corrigé

1) Fonctions auxiliaires (boucle explicite, sans l'opérateur in) :

def est_membre(liste,m):
    for e in liste:
        if e == m:
            return True
    return False

def est_minorant(liste,m):
    for e in liste:
        if e < m:
            return False
    return True

2) Pré-condition : la liste ne doit pas être vide.

def verifie_pre_condition(liste):
    return len(liste)>0

3) Post-condition : m doit être à la fois un élément de la liste et un minorant de la liste (les deux ensemble caractérisent exactement le minimum) :

def verifie_post_condition(liste,m):
    return est_membre(liste,m) and est_minorant(liste,m)
Deux clauses — sans est_membre, m = -100 serait accepté pour [1,2,3] ; sans est_minorant, m = 2 serait accepté.

Exercice 3 — indice de stricte croissance (facile)

Contrainte : indice_stricte_croissance et les fonctions de test ne doivent pas être modifiées. La fonction accepte une liste non vide dont le dernier élément est strictement supérieur au premier, et retourne un indice i tel que liste[i] est strictement supérieur à son prédécesseur.

def verifie_pre_condition(liste):
    return ...

def verifie_post_condition(liste,i):
    return ...

def indice_stricte_croissance(liste):
    assert verifie_pre_condition(liste), 'Pre-condition'
    i = 1
    while liste[i-1]>=liste[i]:
        i += 1
    assert verifie_post_condition(liste,i), 'Post-condition'
    return i
  • 1) Compléter verifie_pre_condition(liste). Indication : vérifier la validité de la taille de la liste avant d'en comparer les éléments.
  • 2) Compléter verifie_post_condition(liste,i). Indications : vérifier la validité de l'indice i avant de comparer des éléments ; il peut exister plusieurs indices valides.
  • 3) Décommenter les tests.
Voir le corrigé

1) Pré-condition : taille ≥ 2 (vérifiée en premier : court-circuit du and), puis dernier élément strictement supérieur au premier.

def verifie_pre_condition(liste):
    return len(liste)>=2 and liste[-1]>liste[0]

2) Post-condition : l'indice i doit d'abord être valide (1 ≤ i < longueur, vérifié en premier), puis on compare liste[i-1] et liste[i] :

def verifie_post_condition(liste,i):
    return 1<=i<len(liste) and liste[i-1]<liste[i]

Les tests passent : par exemple pour [7,4,2,-1,5,5,3,8,8], les indices valides sont 4 et 7 (plusieurs réponses possibles).

Remarque — la pré-condition choisie est une condition suffisante mais pas nécessaire : pour [8,3,5,1] elle n'est pas respectée, et pourtant i=2 convient (5 > 3). Ce n'est pas la plus faible pré-condition possible.

Exercice 4 — réciproques entières (facile)

On cherche la partie entière d'une racine carrée et d'un logarithme, sans aucun calcul flottant (toutes les variables de type int) — par une boucle balayant de façon croissante les solutions possibles.

def racine_entiere(n):
    assert n>=0, 'Pre-condition'
    ...
    assert a>=0 and a**2<=n<(a+1)**2, 'Post-condition'
    return a

def log2_entier(n):
    assert n>0, 'Pre-condition'
    ...
    assert k>=0 and 2**k<=n<2**(k+1), 'Post-condition'
    return k

def logb_entier(n,b):
    assert n>0 and b>=2, 'Pre-condition'
    ...
    assert k>=0 and b**k<=n<b**(k+1), 'Post-condition'
    return k

Compléter (1) racine_entiere(n), (2) log2_entier(n), (3) logb_entier(n,b) (b ≥ 2). La fonction de test se contente d'appeler la fonction : c'est l'assertion de post-condition qui vérifie le résultat.

Voir le corrigé

Même idée dans les 3 cas : balayer les solutions possibles par une boucle croissante, en s'arrêtant juste avant de dépasser n.

def racine_entiere(n):
    assert n>=0, 'Pre-condition'
    a = 0
    while (a+1)**2 <= n:
        a += 1
    assert a>=0 and a**2<=n<(a+1)**2, 'Post-condition'
    return a

def log2_entier(n):
    assert n>0, 'Pre-condition'
    k = 0
    while 2**(k+1) <= n:
        k += 1
    assert k>=0 and 2**k<=n<2**(k+1), 'Post-condition'
    return k

def logb_entier(n,b):
    assert n>0 and b>=2, 'Pre-condition'
    k = 0
    while b**(k+1) <= n:
        k += 1
    assert k>=0 and b**k<=n<b**(k+1), 'Post-condition'
    return k

Vérifié par exécution : racine_entiere sur n=0..999, log2_entier sur 1..999 et log2_entier(2**100-1)==99, logb_entier sur n=1..99 × b=2..10 et deux cas extrêmes (logb_entier(2**100-1,2)==99, logb_entier(5**100-1,5)==99).

Exercice 5 — médiane (facile)

On appelle médiane d'une liste d'entiers toute valeur de cette liste telle qu'au moins la moitié des éléments lui sont inférieurs ou égaux, et qu'au moins la moitié lui sont supérieurs ou égaux (définition volontairement différente de la médiane mathématique : pas de flottants, valeur présente dans la liste).

  • La médiane de [5,4,6,2,0] est 4 (3 valeurs ≤ 4 : 4,2,0 ; et 3 valeurs ≥ 4 : 5,4,6).
  • Les deux médianes acceptées pour [5,2,7,4] sont 4 et 5.
  • La médiane de [1,3,3,5,2,3] est 3 (5 valeurs ≤ 3 et 4 valeurs ≥ 3).
def nombre_inferieurs(liste,valeur):
    ...

def nombre_superieurs(liste,valeur):
    ...

def calculer_mediane(liste):
    n = len(liste)
    assert n>0, 'Pre-condition'
    ...
    assert (
        nombre_inferieurs(liste,mediane)>=(n+1)//2
        and nombre_superieurs(liste,mediane)>=(n+1)//2
    ), 'Post-condition'
    return mediane
  • 1) Compléter nombre_inferieurs (nombre d'éléments ≤ valeur) et nombre_superieurs (nombre d'éléments ≥ valeur).
  • 2) Compléter calculer_mediane (liste non vide de longueur n). On peut utiliser les deux fonctions auxiliaires dans le corps. Contrainte : ne pas modifier liste ni n.
Voir le corrigé

1) Auxiliaires (comptage par balayage) et 2) on trie une copie et on prend l'élément central d'indice (n-1)//2 : c'est toujours un élément de la liste, et par construction du tri au moins la moitié des éléments lui sont ≤ et au moins la moitié lui sont ≥.

def nombre_inferieurs(liste,valeur):
    compte = 0
    for e in liste:
        if e<=valeur:
            compte += 1
    return compte

def nombre_superieurs(liste,valeur):
    compte = 0
    for e in liste:
        if e>=valeur:
            compte += 1
    return compte

def calculer_mediane(liste):
    n = len(liste)
    assert n>0, 'Pre-condition'
    trie = sorted(liste)
    mediane = trie[(n-1)//2]
    assert (
        nombre_inferieurs(liste,mediane)>=(n+1)//2
        and nombre_superieurs(liste,mediane)>=(n+1)//2
    ), 'Post-condition'
    return mediane

sorted(liste) crée une nouvelle liste sans toucher à liste ni à n. Vérifié sur les cas de l'énoncé puis sur 200 listes aléatoires via la post-condition.

Exercice 6 — indice du minimum (facile)

On veut déterminer l'indice où se trouve le minimum d'une liste.

def est_minorant_plage(liste,d,f,m):
    ...

def indice_minimum(liste):
    n = len(liste)
    assert n>0, 'Pre-condition'
    ...
    assert 0<=i_min<n and est_minorant_plage(liste,0,n,liste[i_min]), 'Post-condition'
    return i_min
  • 1) Compléter est_minorant_plage(liste,d,f,m) : True si m est ≤ tous les éléments d'indice i tel que d ≤ i < f (plage [d;f[), False sinon.
  • 2) a) Compléter indice_minimum(liste) (retourne n'importe quel indice du minimum). b) Compléter indice_premier_minimum(liste), dont la post-condition ajoute est_minorant_plage(liste,0,i_min,liste[i_min]+1). c) Compléter indice_dernier_minimum(liste) (avec est_minorant_plage(liste,i_min+1,n,liste[i_min]+1)).

Contraintes : est_minorant_plage n'est appelée que dans les post-conditions ; liste et n ne sont pas modifiées.

Voir le corrigé

1) est_minorant_plage ne parcourt que la plage [d ; f[ :

def est_minorant_plage(liste,d,f,m):
    for i in range(d,f):
        if liste[i]<m:
            return False
    return True

2) a) Balayage classique, en gardant le premier indice qui bat le minimum courant (comparaison stricte <) : cela produit naturellement le premier indice du minimum.

def indice_minimum(liste):
    n = len(liste)
    assert n>0, 'Pre-condition'
    i_min = 0
    for i in range(1,n):
        if liste[i] < liste[i_min]:
            i_min = i
    assert 0<=i_min<n and est_minorant_plage(liste,0,n,liste[i_min]), 'Post-condition'
    return i_min

b) Même algorithme : la comparaison stricte garantit déjà qu'on s'arrête sur le premier indice atteignant le minimum. Seule la post-condition (fournie) ajoute la clause « tout ce qui précède est strictement supérieur ».

def indice_premier_minimum(liste):
    n = len(liste)
    assert n>0, 'Pre-condition'
    i_min = 0
    for i in range(1,n):
        if liste[i] < liste[i_min]:
            i_min = i
    assert (
        0<=i_min<n and est_minorant_plage(liste,0,n,liste[i_min])
        and est_minorant_plage(liste,0,i_min,liste[i_min]+1)
    ), 'Post-condition'
    return i_min

c) Même algorithme avec une comparaison large <= : chaque nouvelle occurrence du minimum (même égale) écrase la précédente : on obtient la dernière occurrence.

def indice_dernier_minimum(liste):
    n = len(liste)
    assert n>0, 'Pre-condition'
    i_min = 0
    for i in range(1,n):
        if liste[i] <= liste[i_min]:
            i_min = i
    assert (
        0<=i_min<n and est_minorant_plage(liste,0,n,liste[i_min])
        and est_minorant_plage(liste,i_min+1,n,liste[i_min]+1)
    ), 'Post-condition'
    return i_min

Aucune des 3 fonctions n'appelle est_minorant_plage dans son corps ; liste et n ne sont jamais modifiées. Vérifié sur des listes aléatoires.

Exercice 7 — indice d'encadrement (facile)

Contrainte : indice_encadrement et les fonctions de test ne doivent pas être modifiées. La fonction accepte une liste non vide liste et un entier valeur supérieur ou égal au premier élément et strictement inférieur au dernier. Elle retourne un indice i tel que valeur >= liste[i-1] et valeur < liste[i].

def verifie_pre_condition(liste,valeur):
    return ...

def verifie_post_condition(liste,valeur,i):
    return ...

def indice_encadrement(liste,valeur):
    assert verifie_pre_condition(liste,valeur), 'Pre-condition'
    i = 1
    while liste[i-1]>valeur or valeur>=liste[i]:
        i += 1
    assert verifie_post_condition(liste,valeur,i), 'Post-condition'
    return i
  • 1) Compléter verifie_pre_condition(liste,valeur) (vérifier la taille avant de comparer des éléments).
  • 2) Compléter verifie_post_condition(liste,valeur,i) (vérifier la validité de i avant de comparer ; plusieurs indices peuvent être valides).
  • 3) Décommenter les tests.
Voir le corrigé

Pré-condition : taille ≥ 2 (court-circuit), puis valeur encadrée (large / stricte) par le premier et le dernier élément :

def verifie_pre_condition(liste,valeur):
    return len(liste)>=2 and liste[0]<=valeur<liste[-1]

Post-condition : indice valide en premier, puis valeur encadrée entre liste[i-1] (inclus) et liste[i] (exclu) :

def verifie_post_condition(liste,valeur,i):
    return 1<=i<len(liste) and liste[i-1]<=valeur<liste[i]

Pour [1,5,0,4] et valeur 1, les indices valides sont 1 et 3.

Exercice 8 — compression RLE (avancé)

decompresser_liste est vérifiée par des tests unitaires ; compresser_liste l'est par un test de post-condition s'appuyant sur decompresser_liste.

Image carrée en niveaux de gris de 8 pixels de côté (0 = noir, 255 = blanc, valeurs intermédiaires = gris) :

255255255255255255255255
255255255255255255255255
2551270000127255
2550012725500255
25502552552552550255
2550012712700255
2551270000127255
255255255255255255255255

La méthode RLE (Run Length Encoding) encode une plage de nombres identiques par le couple [longueur de la plage, nombre répété]. Exemple : [255,255,0,0,0,0,63,63,63,63,127,127,127] s'encode [2,255,4,0,4,63,3,127].

def decompresser_liste(liste_compressee):
    ...

def compresser_liste(liste):
    assert True, 'Pre-condition'
    ...
    assert decompresser_liste(liste_compressee)==liste, 'Post-condition'
    return liste_compressee
  • 1) Compléter decompresser_liste (ne modifie pas son paramètre). Une liste compressée est valide si elle est de longueur paire, si les éléments d'indices pairs (longueurs) sont strictement positifs, et si deux valeurs consécutives (indices impairs) sont distinctes. Sinon, retourner None.
  • 2) Écrire compresser_liste : pas de pré-condition ; post-condition decompresser_liste(liste_compressee)==liste ; ne modifie pas liste.
  • 3) Taux de compression T = 1 − (taille compressée / taille originale) : a) le calculer sur l'image 8×8 (aplatie en une liste de 64 valeurs) ; b) l'afficher en pourcentage.
Voir le corrigé

1) On vérifie la validité (longueur paire, longueurs strictement positives, valeurs consécutives distinctes) avant de reconstruire :

def decompresser_liste(liste_compressee):
    if len(liste_compressee) % 2 != 0:
        return None
    valeurs_repetees = []
    for i in range(0, len(liste_compressee), 2):
        longueur = liste_compressee[i]
        if longueur <= 0:
            return None
        valeurs_repetees.append(liste_compressee[i+1])
    for i in range(1, len(valeurs_repetees)):
        if valeurs_repetees[i] == valeurs_repetees[i-1]:
            return None
    resultat = []
    for i in range(0, len(liste_compressee), 2):
        longueur = liste_compressee[i]
        valeur = liste_compressee[i+1]
        resultat += [valeur]*longueur
    return resultat

2) On balaie la liste en regroupant chaque plage de valeurs identiques consécutives (deux indices i, j délimitent la plage courante) :

def compresser_liste(liste):
    assert True, 'Pre-condition'
    liste_compressee = []
    i = 0
    n = len(liste)
    while i < n:
        j = i
        while j < n and liste[j] == liste[i]:
            j += 1
        liste_compressee += [j-i, liste[i]]
        i = j
    assert decompresser_liste(liste_compressee)==liste, 'Post-condition'
    return liste_compressee

3) Taux de compression sur l'image 8×8 :

image_compressee = compresser_liste(image)
taux = 1 - len(image_compressee)/len(image)
print("{:.1%}".format(taux))

Résultat obtenu par exécution : la liste compressée commence par [17,255,1,127,4,0,1,127,2,255,…] et contient 44 entiers contre 64 dans l'image originale : T = 1 − 44/64 = 0,3125, affiché 31.2% (arrondi de 31,25 %).

Exercice 9 — principe des tiroirs (avancé)

Le principe des tiroirs de Dirichlet affirme que si n chaussettes sont rangées dans m tiroirs avec m < n, alors un tiroir contient au moins deux chaussettes.

  • trouver_elements_identiques(liste) : liste de longueur n, valeurs parmi n-1 possibilités (de 0 à n-2) ; trouver deux indices distincts partageant la même valeur.
  • trouver_valeur_absente(liste) : liste de longueur n, valeurs parmi n+1 possibilités (de 0 à n) ; trouver l'entier entre 0 et n absent de la liste.
def est_liste_bornee(liste,m1,m2):
    ...

def est_valeur_presente(liste,valeur):
    ...

def trouver_elements_identiques(liste):
    n = len(liste)
    assert n>0 and est_liste_bornee(liste,0,n-2), 'Pre-condition'
    ...
    assert 0<=i1<i2<n and liste[i1]==liste[i2]
    return i1,i2

def trouver_valeur_absente(liste):
    n = len(liste)
    assert est_liste_bornee(liste,0,n), 'Pre-condition'
    ...
    assert 0<=valeur<=n and not est_valeur_presente(liste,valeur)
    return valeur
  • 1) Écrire est_liste_bornee(liste,m1,m2) (True si tous les éléments e vérifient m1 ≤ e ≤ m2) et est_valeur_presente(liste,valeur).
  • 2) Compléter trouver_elements_identiques. Exemple : [2,0,3,4,5,3,1] (n=7) → i1=2, i2=5 (valeur 3).
  • 3) Compléter trouver_valeur_absente. Exemple : [2,0,3,7,5,6,1] (n=7) → valeur=4.
Voir le corrigé

1) Auxiliaires puis 2) les valeurs sont dans [0 ; n-2], donc n-1 valeurs possibles pour n éléments : on mémorise, pour chaque valeur v, le premier indice où elle apparaît (les « tiroirs » sont les valeurs, les « chaussettes » les indices). 3) Même idée avec n+1 valeurs possibles pour n éléments : on marque les valeurs présentes puis on cherche la première non marquée.

def est_liste_bornee(liste,m1,m2):
    for e in liste:
        if not (m1<=e<=m2):
            return False
    return True

def est_valeur_presente(liste,valeur):
    for e in liste:
        if e==valeur:
            return True
    return False

def trouver_elements_identiques(liste):
    n = len(liste)
    assert n>0 and est_liste_bornee(liste,0,n-2), 'Pre-condition'
    vu = [-1]*(n-1)
    i1, i2 = 0, 0
    for i in range(n):
        v = liste[i]
        if vu[v] != -1:
            i1, i2 = vu[v], i
            break
        vu[v] = i
    assert 0<=i1<i2<n and liste[i1]==liste[i2]
    return i1,i2

def trouver_valeur_absente(liste):
    n = len(liste)
    assert est_liste_bornee(liste,0,n), 'Pre-condition'
    vu = [False]*(n+1)
    for e in liste:
        vu[e] = True
    valeur = 0
    while vu[valeur]:
        valeur += 1
    assert 0<=valeur<=n and not est_valeur_presente(liste,valeur)
    return valeur

Vérifié sur les exemples de l'énoncé et sur 200 listes aléatoires.

Exercice 10 — les quatre carrés de Lagrange (expert)

Le théorème des quatre carrés de Lagrange affirme que tout entier n ≥ 0 s'écrit comme somme de quatre carrés : \(n = a^2 + b^2 + c^2 + d^2\).

def quatre_carres(n):
    assert n>=0, 'Pre-condition'
    ...
    assert a**2+b**2+c**2+d**2==n, 'Post-condition'
    return a,b,c,d

Compléter quatre_carres(n) qui retourne quatre entiers a, b, c, d vérifiant la post-condition.

Voir le corrigé

Recherche exhaustive bornée par math.isqrt : on essaie a du plus grand possible vers 0, puis b, puis c, et on déduit d en testant si le reste est un carré parfait. Dès qu'une solution est trouvée, on sort des 3 boucles via un indicateur testé après chaque boucle interne.

import math

def quatre_carres(n):
    assert n>=0, 'Pre-condition'
    a = b = c = d = 0
    amax = math.isqrt(n)
    for a in range(amax, -1, -1):
        reste_a = n - a*a
        bmax = math.isqrt(reste_a)
        trouve = False
        for b in range(bmax, -1, -1):
            reste_b = reste_a - b*b
            cmax = math.isqrt(reste_b)
            for c in range(cmax, -1, -1):
                reste_c = reste_b - c*c
                d = math.isqrt(reste_c)
                if d*d == reste_c:
                    trouve = True
                    break
            if trouve:
                break
        if trouve:
            break
    assert a**2+b**2+c**2+d**2==n, 'Post-condition'
    return a,b,c,d
Piège Python — tester if trouve: break en tout début de boucle est faux : la variable de boucle est déjà réaffectée à la valeur suivante avant l'exécution du corps (pour n=1, a valait 0 au lieu de 1). Il faut sortir juste après avoir trouvé, tant que la même valeur de a/b est active.

Vérifié pour tout n de 0 à 999 : quatre_carres(0)==(0,0,0,0), quatre_carres(1)==(1,0,0,0), quatre_carres(7)==(2,1,1,1), quatre_carres(999)==(31,6,1,1).

À retenir —
  • Spécifier avant d'implémenter : la pré-condition délimite le domaine où le problème a un sens, la post-condition caractérise le résultat — indépendamment de l'algorithme choisi.
  • Toujours vérifier la taille/validité d'un indice avant de comparer des éléments : l'évaluation paresseuse de and/or évite une IndexError (exercices 3 et 7).
  • Fonctions auxiliaires (est_membre, est_minorant, est_minorant_plage, est_liste_bornee…) : la post-condition devient lisible et réutilisable.
  • Une même spécification a plusieurs implémentations : indice_minimum, indice_premier_minimum, indice_dernier_minimum ne diffèrent que par < ou <= dans la boucle.
  • Piège Python : tester la condition de sortie en tête d'une boucle for ne préserve pas la variable de boucle de l'itération précédente — sortir juste après avoir trouvé (exercice 10).
  • Principe des tiroirs : un tableau « vu » indexé par les valeurs possibles est plus simple et plus rapide qu'une recherche de paires imbriquées (exercice 9).
