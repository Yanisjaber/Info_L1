Deux idées dans ce cours : (1) un tableau ou une matrice est un type abstrait qui ne s'utilise qu'avec quelques opérations (créer, longueur, lire, écrire) ; (2) la complexité mesure le coût d'un algorithme en fonction de la taille de son entrée, et permet de choisir entre plusieurs algorithmes qui résolvent le même problème.

Partie 1 — Le type abstrait Tableau et Matrice

Type abstrait — décrit ce qu'on peut faire avec une donnée (ses opérations autorisées), sans dire comment c'est fait en mémoire. Il sépare le client (le code qui utilise le type, qui ne connaît que les opérations) du prestataire (le code qui l'implémente). Une structure de données définit en plus son implémentation, c'est-à-dire sa mise en œuvre matérielle (comment elle est représentée en mémoire).

Pourquoi ne pas utiliser directement les list de Python ? Parce que le but de l'UE est d'apprendre des notions d'algorithmique indépendantes du langage. Si on utilisait toutes les possibilités des listes Python (append, insert, pop…), le raisonnement ne se transposerait plus en C, Java, etc. On se restreint donc à un socle minimal d'opérations, disponible dans (presque) tous les langages.

Exemples de types — le type int de Python a pour espace de valeurs l'ensemble des entiers relatifs (ℤ) et pour opérations autorisées +, -, %, etc. Le type bool a pour espace de valeurs {False, True} et pour opérations not, and, or, ==. Chaque opération se spécifie comme une fonction : ses paramètres sont les opérandes, sa valeur de retour est le résultat, et sa pré-condition / post-condition précisent dans quel cas elle s'applique et ce qu'elle garantit.

Le type abstrait Tableau

Un tableau mémorise une séquence d'éléments avec 3 règles : le nombre d'éléments est fixe, tous les éléments ont le même type, et chaque élément est repéré par sa position (indice).

Interdits — pas d'append, insert ou pop : ces méthodes changent la longueur de la liste, ce qui casserait la règle « taille fixe » du tableau.
def creer_tableau(longueur, defaut):
    assert longueur >= 0, 'Pre-condition'
    return [defaut] * longueur

tableau = creer_tableau(20, 0)   # tableau de 20 entiers, tous à 0
tableau[0] = int(input())        # écriture
tableau[1] = 2 * tableau[0]      # lecture puis écriture

Pourquoi ces 4 opérations et pas d'autres ?

Elles collent à ce qu'une zone contiguë de mémoire permet de faire efficacement : chaque case occupe une taille fixe, et l'adresse de l'élément i se calcule directement par adresse(tableau[0]) + i × taille_case. C'est pourquoi en C un tableau a une taille fixée une fois pour toutes à sa création :

int tableau[20] = {0};        // 20 cases, valable uniquement pour 0
scanf("%d", &tableau[0]);     // écriture
tableau[1] = 2 * tableau[0];  // lecture puis écriture

Exercice corrigé — la fonction deplacer

def deplacer(tableau, i_source, i_destination):
    valeur = tableau.pop(i_source)
    tableau.insert(i_destination, valeur)

1) Ce qu'elle fait : elle retire l'élément situé à l'indice i_source puis le réinsère à l'indice i_destination : elle déplace un élément dans la liste, en décalant tous les éléments entre les deux positions.

2) Pourquoi ça viole le type Tableau : pop et insert sont des opérations interdites, car elles changent la longueur de la liste (même temporairement, le temps d'un appel). Un tableau n'autorise que lire/écrire à un indice existant.

3) Correction : on ne peut utiliser que lire et écrire ; on recopie « à la main » les éléments un par un, en décalant dans le bon sens :

def deplacer(tableau, i_source, i_destination):
    assert 0 <= i_source < len(tableau), 'Pre-condition'
    assert 0 <= i_destination < len(tableau), 'Pre-condition'
    valeur = tableau[i_source]
    if i_source < i_destination:
        for i in range(i_source, i_destination):
            tableau[i] = tableau[i + 1]
    else:
        for i in range(i_source, i_destination, -1):
            tableau[i] = tableau[i - 1]
    tableau[i_destination] = valeur

4) Contrainte à garantir : tous les éléments doivent être conservés, seulement réordonnés — ni perdu, ni dupliqué. La version corrigée le garantit naturellement : elle ne fait que des décalages internes au tableau, dont la longueur ne change jamais.

Exemple — t = [10, 20, 30, 40, 50] ; après deplacer(t, 1, 3), t vaut [10, 30, 40, 20, 50] (l'élément 20 est passé de l'indice 1 à l'indice 3, 30 et 40 ont reculé d'une case).

Le type abstrait Matrice

Une matrice est un tableau à deux dimensions (lignes × colonnes), utile pour représenter des données 2D (images, grilles, transformations géométriques…). En Python restreint : une liste non vide de listes non vides, toutes de même longueur.

def creer_matrice(nb_lignes, nb_colonnes, defaut):
    assert nb_lignes > 0 and nb_colonnes > 0, 'Pre-condition'
    matrice = [None] * nb_lignes
    for i in range(nb_lignes):
        matrice[i] = [defaut] * nb_colonnes
    return matrice

matrice = creer_matrice(19, 13, 0)   # 19 lignes, 13 colonnes
nb_lignes  = len(matrice)
nb_colonnes = len(matrice[0])
matrice[3][4] = int(input())          # écriture à la ligne 3, colonne 4

Même logique que pour le tableau : dimensions et type fixés à la création ; aucune méthode qui changerait la longueur d'une des listes n'est autorisée.

Piège classique — [[0] * 13] * 19 crée 19 fois la même ligne (alias) : modifier une case modifie toute la colonne. C'est pourquoi creer_matrice crée une nouvelle liste [defaut] * nb_colonnes pour chaque ligne.

Deux motivations : représenter des données en 2D (une image en niveaux de gris est une matrice de pixels, un écran une matrice de couleurs), et représenter la notion mathématique de matrice (transformations du plan ou de l'espace). Une rotation 3D peut s'écrire comme une matrice 3×3 :

rot = [
    [ 0, 1, 0],
    [-1, 0, 0],
    [ 0, 0, 1]
]

Partie 2 — Complexité

Complexité — quantité de ressources (temps, mémoire) qu'un algorithme consomme, exprimée en fonction de la taille de son entrée (longueur d'un tableau, valeur d'un entier…). Plusieurs algorithmes peuvent résoudre le même problème : la complexité permet de choisir le plus adapté, en particulier pour de grandes entrées.
Rappels de vocabulaire —
  • Problème : caractérisé par sa spécification, c'est-à-dire une pré-condition (ce qu'on suppose sur l'entrée) et une post-condition (ce que doit garantir la sortie).
  • Implémentation : une fonction concrète qui respecte cette spécification.
  • Algorithme : l'ensemble des opérations qui permettent de respecter la spécification, indépendamment du langage de programmation utilisé.

Interprétation (question 4) : à chaque fois que n est multiplié par 10, le temps l'est aussi (facteur proche de 10 sur toute la table). C'est la signature d'une complexité linéaire, notée O(n) : la fonction fait une boucle de n itérations, donc son temps est proportionnel à n.

Estimation pour n = 1050 (question 5) : le temps est proportionnel à n. Comme 1010 prend 457 s et que 1050 est 1040 fois plus grand, il faudrait environ 457 × 1040 secondes, soit de l'ordre de 1035 années — bien plus que l'âge de l'univers. Un algorithme en O(n) tout à fait correct, mais totalement impraticable pour de très grandes entrées.

D'où l'intérêt de somme_entiers_2, qui utilise la formule \(\frac{n(n+1)}{2}\) : un seul calcul, quelle que soit la taille de n. Sa complexité est constante, O(1) : sur la même machine, l'appel avec n = 1050 prend environ 1,9 × 10-6 s, comme pour n'importe quel n.

def somme_entiers_2(n):
    return n * (n + 1) // 2

Application : la racine carrée entière

Problème : étant donné un entier positif n, déterminer la partie entière de sa racine carrée.

Spécification — type du paramètre : n entier ; type du retour : a entier. Pré-condition : n >= 0. Post-condition : a >= 0 and a**2 <= n < (a+1)**2.

Algorithme 1 — par balayage : on part de a = 0 et on incrémente jusqu'à trouver la solution.

def racine_entiere_1(n):
    assert n >= 0, 'Pre-condition'
    a = 0
    while (a + 1)**2 <= n:
        a += 1
    assert a >= 0 and a**2 <= n < (a + 1)**2, 'Post-condition'
    return a

Algorithme 2 — par dichotomie : on établit une zone de recherche [a, b) contenant la solution. On calcule le carré du milieu m = (a+b)//2 : si m**2 <= n, la solution est dans la moitié droite, sinon dans la moitié gauche. On répète en coupant l'intervalle en deux jusqu'à ce qu'il soit de longueur 1. À l'initialisation, a = 0 et b = n+1.

Invariant — tout au long de la boucle : a**2 <= n < b**2. Quand b - a == 1, on a a**2 <= n < (a+1)**2 : c'est exactement la post-condition. (Le support formule la règle « inférieur à n » ; le code utilise bien <=.)

Exercice — écrire racine_entiere_2 par dichotomie

Même spécification que racine_entiere_1, avec l'algorithme par dichotomie. Cas particulier utile à vérifier : n = 1 (on initialise a = 0, b = n+1 = 2).

def racine_entiere_2(n):
    assert n >= 0, 'Pre-condition'
    a, b = 0, n + 1
    while b - a > 1:
        m = (a + b) // 2
        if m**2 <= n:
            a = m
        else:
            b = m
    assert a >= 0 and a**2 <= n < (a + 1)**2, 'Post-condition'
    return a

Déroulé pour n = 1 : a=0, b=2 → m=1, m2=1 <= 1 donc a=1 → b-a=1, on s'arrête : a=1. On vérifie bien 12 <= 1 < 22. Les cas n = 0 et n = 17 se déroulent sur le même principe (n = 0 : b-a = 1 d'emblée, la boucle ne s'exécute pas, a = 0 ; n = 17 : a = 4).

Nombre d'itérations dans le pire des cas : à chaque tour, la longueur de la zone de recherche est divisée par 2 ; elle part de n+1 et s'arrête à 1. Il faut donc environ log2(n) itérations, contre \(\sqrt{n}\) pour le balayage — nettement moins dès que n est grand.

Les deux graphes du cours

Zoom sur l'axe des temps (échelle en microsecondes) : pour de très petits n (jusqu'à environ 25) les deux algorithmes se valent ; ensuite le balayage décolle, tandis que la dichotomie croît régulièrement — une droite sur une échelle logarithmique en x, signature de O(log n).

À retenir —
  • Un tableau/une matrice, c'est 4 opérations et rien d'autre : créer, longueur, lire, écrire. Toute méthode qui changerait la taille (append, insert, pop) est hors-jeu.
  • Pour reconnaître une complexité expérimentalement : multiplier n par 10 et regarder le facteur sur le temps — facteur ≈ 10 : O(n) ; facteur ≈ 100 : O(n2) ; facteur quasi nul : O(1) ou O(log n).
  • Balayage vs dichotomie : même résultat, complexités très différentes (O(\(\sqrt{n}\)) contre O(log2 n)). Un bon algorithme peut rendre praticable ce qu'un algorithme correct mais naïf ne permet pas.
